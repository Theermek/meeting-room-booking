# Meeting room booking — working notes

Take-home assignment. Book one meeting room inside a 09:00–18:00 workday: view a day,
create / edit / delete bookings, under strict business rules.

Stack: Next.js 16.4 (App Router, Turbopack) · React 19.3 · TypeScript strict ·
Tailwind v4 · TanStack Query v5 · react-hook-form + zod 3 · Radix Dialog · date-fns +
date-fns-tz · Vitest.

## The one rule that matters

**`src/domain/` owns every business rule.** It is pure TypeScript and imports nothing from
`react`, `next`, or `fetch`. Both the Route Handler and the form call the same
`validateBooking()`. Adding or changing a rule means editing `src/domain/booking.ts` — never
a component, never a route, and never both.

Dependency flow is one-way:

    features/ → lib/api/ → ⇄HTTP⇄ → app/api/ → server/ → domain/

`features/` may also import `domain/` directly (for client-side pre-validation).
Nothing imports in the other direction.

## Conventions

- **`src/lib/api/` is the only place that calls `fetch`.** Swapping in a real backend must
  mean editing `lib/api/bookings.ts` and nothing else.
- **`now: Date` is always an injected parameter.** No domain function reads the clock itself —
  that is what makes "no booking in the past" testable.
- **One timezone.** `APP_TIMEZONE` in `src/domain/constants.ts`, used on client and server
  alike. Vercel runs in UTC, so a hidden `new Date()` would make client and server disagree
  about what "past" means.
- **Touching edges are not a conflict.** `overlaps` is strict: `a.start < b.end && b.start < a.end`.
  10:00–11:00 and 11:00–12:00 are both valid.
- **Times are `"HH:mm"` strings, dates are `"YYYY-MM-DD"` strings** across the wire and the
  domain. Convert to minutes-since-midnight for arithmetic, never to `Date`.
- **A finished booking is immutable.** Once its end time has passed it cannot be edited or
  deleted, enforced in `assertStillMutable()` on the server. The boundary is the end time: a
  meeting that is still running stays editable.
- **A 409 from the server is expected, not a bug.** The UI keeps the user's input, refetches
  the day, and explains the conflict. Never reset a form on a failed submit.
- **Real `<button>` elements only** — no clickable `div`s. Every state that is shown with
  color is also shown as text.

## Notes

- `AGENTS.md` is generated by `next dev` and holds Next.js 16's own agent rules. Leave it to
  Next; project rules go here.
- `cacheComponents` is deliberately **off** in `next.config.ts` — all data flows through
  client-side React Query, so there is nothing to prerender, and leaving it on risks baking
  a snapshot of the in-memory store into the build.
- The store is an in-memory module singleton and resets on serverless cold start. It reseeds
  deterministically so the demo is never empty.
- **Commits are the user's.** Do not run `git commit`, `git push`, or create remotes; stop at
  a clean working tree and say so.
